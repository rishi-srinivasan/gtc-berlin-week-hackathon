# PII Gateway: Results

**German PII redaction with a distilled small model.** Support emails and call notes contain names, IBANs, tax IDs and depot numbers. A small self-hosted model finds the PII, code swaps it for placeholders such as `[IBAN_1]`, only the masked text reaches the frontier LLM, and the reply is rehydrated with the original values.

## The model

| | |
|---|---|
| Student | Qwen3-1.7B, fine-tuned with distil labs |
| Teacher | gpt-oss-120b |
| Task | Extract PII entities from German text as JSON, across 22 PII classes |
| Training data | 128 synthetic rows generated by the teacher from 100 seed examples |
| Test set | 300 German messages (180 from a public Hugging Face German PII dataset, 120 synthetic broker messages) |
| Serving | distil labs inference endpoint |

## 1. Fine-tuning works: 1.7B model, large gains over the untuned base

Scores on the 300-message test set.

| Metric | Untuned 1.7B | Teacher 120B | Fine-tuned 1.7B |
|---|---|---|---|
| Rouge (text overlap) | 58.0% | 86.6% | **85.6%** |
| Exact match | 3.0% | 8.3% | **39.3%** |
| LLM judge, against reference | 3.7% | 55.7% | **42.0%** |
| LLM judge, reference-free | 6.3% | 84.7% | **52.0%** |

- Exact match went from 3% to 39%, and the fine-tuned student exceeds the teacher (8.3%) because it learned the exact output format.
- Rouge is within 1 point of the 120B teacher.
- On the reference judge the student recovers 74% of the gap between the untuned model and the teacher. On the reference-free judge it recovers 58%.
- It does this with a model about 70× smaller than the teacher.

## 2. Why it matters: PII leaks without a model

Leak rate is the share of messages where at least one real PII value is still readable after masking. Lower is better.

| System | Leak rate |
|---|---|
| Off-the-shelf PII model (GLiNER, German) | 84.7% |
| Teacher, 120B | **28.3%** (95% upper bound 33.7%) |

Teacher detail (300 messages):

| | |
|---|---|
| Leak rate on synthetic broker messages | 10.8% |
| Leak rate on public-dataset messages | 40.0% |
| Recall on critical identifiers (IBAN, tax and ID numbers, cards) | 78.7% |
| Recall on high-risk identifiers | 89.2% |
| Failed calls | 0 |
| Median latency | 8.5 s per message |

Per-class recall (teacher):

- **Strong:** age and salary 100%, tax number 96%, IP address 95%, credit card 94%.
- **Weaker:** ID card number 32% and account number 24%.

## 3. What the metrics mean

| Metric | Meaning |
|---|---|
| **Rouge** | Text overlap between the model's answer and the reference. Lenient: mostly-correct JSON scores high. |
| **Exact match** | Scores 1 only when the full entity list equals the reference. Very strict: one missed or extra entity fails the message. |
| **LLM judge, against reference** | An LLM compares the answer with the reference and marks it good or bad. It tolerates harmless differences in wording or order. |
| **LLM judge, reference-free** | An LLM decides whether the answer solves the task without seeing the reference. It is not affected by imperfect reference labels. |
| **Gap closed** | `(tuned − untuned) / (teacher − untuned)`: how much of the teacher's advantage the small model captured. |
| **Leak rate** | The share of messages where any real PII is still readable after masking. This is the business metric. The 95% upper bound is a statistical limit on the true rate. |
| **Recall** | Of all real PII values, the share the model found. A miss is a leak, so recall is the safety metric. |
| **Precision** | Of all values the model flagged, the share that were real PII. Low precision means over-masking, which costs usefulness, not safety. |
| **Critical / high recall** | Recall limited to the most sensitive classes (IBAN, tax and ID numbers, cards) and the next tier. |
| **Median latency** | The typical response time per message, which is the delay the gateway adds. |

## 4. Takeaways

1. Without a dedicated model, PII leaks in the large majority of messages (84.7% with a standard German PII model).
2. A 120B teacher cuts leakage to 28%, but at about 8 s per message and with a large self-hosted footprint.
3. A fine-tuned 1.7B model reaches teacher-level text overlap, beats it on exact match, and recovers 58–74% of the teacher's judged quality, from only 128 synthetic training rows.
4. Next steps: train on the full synthetic set (about 5,000 rows) and add real traffic from the inference endpoint's Langfuse traces to improve the weak classes (ID card and account numbers).
